# Aftermath Hedge Bot

A command-line bot for the `standard Perpetuals Account (maker) → user's own Vault (taker hedge)` strategy.

This is not a custodial service. USDC stays inside Aftermath objects owned by the user's Sui wallet. The bot never asks for the seed phrase or private key of the owner's wallet. Configuration is command-line only.

> Pre-release software. Start with a small OI target. Near-zero delta does not guarantee profit: fees, slippage, funding, execution gaps, and price movement before the hedge still apply.

## Quick start

### 1. Prepare an Account and Vault in the official Aftermath app

Open [Aftermath Perpetuals](https://aftermath.finance/perpetuals) with your regular Sui wallet:

1. Create a standard `Perpetuals Account` and deposit USDC for maker orders.
2. Create a personal `Vault` under the same owner wallet and deposit separate USDC for taker hedges.
3. Set `Lock period = 0`, `Force-withdraw delay = 0`, and, for a personal test Vault, `Performance fee = 0`.

The Account and Vault use separate collateral. Fund both. You never need to send trading funds to an address generated by the bot.

### 2. Install the bot

You need Git, Node.js `22.13+`, and a supported Sui Wallet browser extension.

```bash
git clone https://github.com/hatredarc/Aftermath-Hedge-Bot.git
cd Aftermath-Hedge-Bot
npm install
npm run setup
```

The setup wizard asks for the owner wallet address, lets you select one of its detected Accounts and Vaults, and asks for strategy settings. Use these conservative values for the first test:

- `Target OI`: `100 USD`
- `Maker limit order size`: `10 USD`
- Initial markets: `BTC,ETH,SUI,SOL`

### 3. Approve once in your wallet

The terminal prints a URL such as `http://localhost:PORT/`. Open it in Chrome or Edge using the browser profile that contains your enabled Sui Wallet extension. Do not open it in an in-app or private browser where extensions are unavailable. The page detects wallets that register after the page has loaded and lets you choose one when several are installed.

The page runs only on your computer and displays the full contents of one transaction before you sign it. That transaction:

1. grants the locally generated Agent Wallet trading-only access to the selected Account;
2. grants the same Agent Wallet trading-only access to the selected Vault;
3. sends `0.05 SUI` to the Agent Wallet for gas.

The Agent Wallet may trade, but cannot withdraw collateral, remove USDC from the Vault, or grant permissions to another address. Its private key is saved locally in `.env.agent` and is excluded from Git.
This safety-first release does not request any fee approval and does not add a developer fee to orders.

### 4. Verify and start live trading

```bash
npm run verify
npm run dry-run
npm run start:live
```

`start:live` repeats the preflight checks. If Agent access, Vault access, account state, market leverage, or executable order-book depth is invalid, no live PTB is submitted.

Press `Ctrl+C` to stop. Never run two instances with the same Agent Wallet.

## Subsequent starts

After the one-time setup, run:

```bash
npm run start:live
```

`npm run start` runs a continuous safe dry-run without submitting transactions.

Useful checks:

```bash
npm run verify
```

## Configuration

```bash
npm run cli -- config show --config classic-flow.config.json
npm run cli -- config set BTC oi 2000 --config classic-flow.config.json
npm run cli -- config set BTC size 50 --config classic-flow.config.json
npm run cli -- config set BTC chase 2 --config classic-flow.config.json
npm run cli -- config set BTC band 250 --config classic-flow.config.json
npm run cli -- config set BTC impact 3 --config classic-flow.config.json
npm run cli -- config set BTC leverage auto --config classic-flow.config.json
```

- `oi`: target matched OI per side, in USD.
- `size`: size of one maker limit order, in USD.
- `chase`: price movement allowed before replacing the bot's order, in bps.
- `band`: permitted OI movement around the target during FLOW, in USD.
- `impact`: maximum maker-fill-to-Vault-VWAP execution gap allowed for a hedge, in bps. This includes thin top-of-book levels; it is not a raw BBO spread.
- `leverage: auto`: the bot reads the current initial-margin requirement from Aftermath and caps strategy leverage at 15x.

## Strategy lifecycle

1. `BUILD`: the Account builds one side using one PostOnly maker order per active market.
2. `SYNC`: every actual maker fill is mirrored by an opposite Vault taker order; new maker orders pause until the delta is hedged.
3. `FLOW`: near the OI target, the Account may keep one bid and one ask per active market and rotates volume inside the configured band.
4. Reducing `oi` makes the bot reduce the Account position and then send the corresponding reduce-only Vault hedge.
5. Auto Top 4 continuously ranks BTC/ETH/SUI/ZEC/SOL using cumulative depth and VWAP. It trades four markets, keeps one as standby, and rotates only after the better candidate remains valid for 60 seconds. A single tiny order cannot trigger a switch.

Market IDs, tick sizes, lot sizes, minimum order values, and leverage limits are loaded from the current Aftermath market metadata at runtime. They are not copied into the source code.

During `SYNC`, the Vault immediately takes any available slice inside the configured `impact` cap. It keeps checking fresh depth for 15 seconds; after that it may finish the remaining delta up to a hard 30 bps cap. A prospective maker order is not posted if its full hedge is already worse than the hard cap.

## Security

- Never publish `.env.agent` or `classic-flow.config.json`.
- Never enter the owner wallet seed phrase or private key in the terminal or local setup page.
- The setup page listens only on `127.0.0.1`, loads no remote JavaScript, and closes after approval.
- The Agent Wallet cannot withdraw funds, but it can still create trading losses. Only use collateral you can afford to risk.
- Revoke the Account Agent and Vault Assistant capabilities with the owner wallet to disable the bot's access.
